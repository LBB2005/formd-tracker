# Audit, 2026-10-25: 15 flaws and their fixes

Found by querying the built database, reading the code and CI logs. Each fix is specific
enough to check. Outcomes are filled in under **Result** once the work lands.

## Data correctness

**1. Duplicate original filings are counted twice.**
2,859 pairs of original Form Ds come from the same CIK, filed within 7 days, with the same
first-sale date, offering amount and amount sold ($14.2B; 339 are startup raises, 1,808
funds). Example: "Island Green AD-I LP" filed 0002153787-26-000001 and -000002 on 2026-10-02.
*Fix:* in `sql/20_offerings.sql`, mark the later of each identical pair with
`duplicate_of` (the earlier offering_id) and set `is_new_in_window = false` for it, so
counts and dollar totals take it once. Add a data check reporting how many were collapsed,
and a unit test.

**2. 1,372 entities named "Fund" are classed as operating companies.**
"Hyla Fund III, LLC", "TR3 Capital Fund VI LLC", "WWC GEM Investment Fund II, LP" filed under
industries like "Other", so the fund rules never fired, and some count as startup raises.
*Fix:* in `sql/30_classify.sql`, a non-corporation whose name has a whole-word "Fund"
becomes a fund (or `other_investing` / `real_estate` for oil-and-gas, energy and
real-estate industries); corporations keep the current rules. Measure the change and test it.

**3. Manager keys drop leading letters.**
"n2 Venture Capital Fund I, LP" gets manager `2 venture capital`.
*Fix:* find the regex in the manager-key logic that strips the leading token and correct
it; add a test for this name and the other leading-digit/short-token keys (79 in all).

**4. The Methodology accuracy row grades rules that no longer run.**
"SPV vs blind pool: 49% correct" scores the vehicle type frozen in the review sample, not
today's rules (20 of 35, 57%), and today's data has hand overrides applied, so it can't be
re-scored from the site.
*Fix:* keep the pre-override rule result as `rule_vehicle_type` (and `rule_kind`) in
`offering_class`, export it with the review sample, and have Methodology score labels
against the current rules.

## Site

**5. The Findings page is hard-coded.** Its numbers (75%, 58%, 3x, 1.4–1.6x, three in four)
will drift as the data refreshes daily.
*Fix:* compute each figure in `site/src/findings.md` from the same Parquet files the other
pages use, keeping the wording.

**6. The Methodology page describes the wrong tie-break.** It says "a local language
model", but CI sends ambiguous homepages to Claude through the Batches API.
`pyproject.toml` still says "SF and LA" only.
*Fix:* correct both.

**7. AI accuracy is measured on SF/LA only but shown everywhere.** Precision and recall come
from SF/LA labels; the AI charts let readers pick Chicago or "All US".
*Fix:* when a metro outside SF/LA (or All US) is selected on an AI view, show a one-line
notice that tag accuracy was measured in SF/LA; say the same on Methodology.

**8. Shared links have no preview, and the site never links to its source.**
No `og:` or description tags; no GitHub link.
*Fix:* add description and Open Graph tags in `observablehq.config.js` and a repository link
in the footer.

**9. Several pages are heavy for phones.** Map and Fund managers pull about 10.7 MB, Funds
and Overview about 6.9 MB.
*Fix:* export page-specific Parquet files with only the columns each page reads, and record
before/after sizes.

## Pipeline and CI

**10. No spending cap on Claude batches.** The first keyed run submitted 2,645 requests to
Opus 5.5 with no ceiling.
*Fix:* a `CLAUDE_MAX_USD` limit per run (estimated from token counts and batch prices),
submitting up to the cap and leaving the rest for the next run; print the estimate.

**11. The quote-verification gate has no tests.** `claude_judge.interpret` decides whether
a "yes" counts, and nothing tests it.
*Fix:* unit tests for verified quotes, invented quotes, quotes without an AI term,
refusals and malformed JSON.

**12. Queued CI runs build stale code and collide.** A `workflow_dispatch` run queued
behind another checks out the SHA from when it was queued, then fails to rebase its binary
`data/enrich` commit (run 39891901969).
*Fix:* check out the latest `main` in the workflow, and make the save step retry from fresh
`origin/main` on a conflict instead of failing.

**13. Actions run on deprecated Node 20.** Every run warns that checkout, cache,
setup-node, setup-uv and the Google actions target Node 20.
*Fix:* bump each action to its current major version that runs on Node 24 (checked
against the actions' release lists).

**14. A permanent warning trains people to ignore warnings.** "2021q1: 12,328 -> 14,880"
fires on every build; it is the 2021 boom, not a fault.
*Fix:* allow-list known, explained swings in `pipeline/checks.py`, still printed as INFO.

**15. An abandoned experiment's SDK is a required dependency.** The Jev second labeller
was dropped on 2026-10-19, but `typesafe-sdk` installs on every CI run.
*Fix:* move it to an optional dependency group and import it only inside `pipeline/jev.py`.

## Not fixable by code

- SPV vs blind-pool accuracy (20 of 35) needs more hand labels before more rules; rules fitted
  to 35 funds would be fitted to the sample.
- AI-tag accuracy outside SF/LA needs labels from those metros.
